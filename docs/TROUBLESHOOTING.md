# 트러블슈팅

실제로 겪은 문제와 해결 방법을 정리했습니다.
- **A**는 프로젝트를 만들면서 해결한 문제입니다. 코드 주석과 커밋 기록을 바탕으로 썼습니다.
- **B**는 끝난 프로젝트를 포트폴리오로 정리하면서(2026년 10월) 찾아 고친 문제입니다.

---

## A. 프로젝트 진행 중

### A1. 외부 AI 대신 로컬 AI로 바꾸기
- **문제:** 처음에는 Gemini API로 챗봇을 만들었습니다. 외부 AI는 API 키를 관리해야 하고, 쓸수록 비용과 호출 제한이 생깁니다.
- **해결:** Ollama로 `qwen2.5:3b` 모델을 내 PC에서 돌리도록 바꿨습니다. 모델 이름, 주소, 답변의 자유도(temperature)는 설정값으로 빼서 코드 수정 없이 바꿀 수 있게 했습니다.
- **대가:** 작은 모델이라 느리고, 말을 지어내는 일이 더 잦았습니다. 그래서 A2처럼 AI가 맡는 일을 줄였습니다.

### A2. 작은 AI 모델이 말을 지어내는 문제
실제로 겪은 경우와 대응입니다 (코드 주석에 기록됨).

| 겪은 문제 | 대응 |
|---|---|
| "스터디룸에서 스트리밍 시작"처럼 없는 기능을 안내함 | AI에게 서비스 설명을 함께 보내고, "방송 보기"와 "방송 만들기"를 코드로 구분해서 알려 줌 |
| 페이지 주소를 AI에게 맡기면 없는 주소로 보낼 위험 | AI는 주소를 만들지 않음. 서버가 정한 목적지 버튼만 보냄 |
| "인기 방송"을 물으면 유튜브 이야기를 함 | AI 대신 DB에서 실제 방송을 세어서 답함 |
| 한국어 답변에 한자·일본어가 섞임 | 답변을 보내기 전에 걸러 냄 |
| "뭘 배워야 할지 모르겠어"에 긴 일반론을 늘어놓음 | 정해 둔 안내 문구로 관심 분야를 되물음 |

### A3. 이전 대화가 엉뚱하게 섞이는 문제
- **문제:** "방송 보고 싶어" 다음에 "자바 문제 내줘"라고 하면 문제에 방송 이야기가 섞였습니다.
- **해결:** 대화 기억(Redis)은 유지하되, 문제 출제처럼 앞 대화가 필요 없는 요청은 대화 기록을 빼고 AI에게 보냅니다.

### A4. 결제 금액과 결제 시점
- **문제:** 브라우저가 보낸 금액을 그대로 믿으면 금액을 바꿔서 결제할 수 있습니다. 또 승인만 하고 결제하지 않은 상담이 캘린더에 남으면 안 됩니다.
- **해결:** 결제 승인은 서버만 요청하고, 그 전에 주문자와 금액을 DB 값과 비교합니다. 멘토링 일정은 결제가 끝난 뒤에만 캘린더에 넣습니다.

### A5. 남의 채팅방을 구독할 수 있는 문제
- **문제:** 채팅방 주소는 예약 번호로 정해집니다. 서버가 막지 않으면 번호만 바꿔서 남의 채팅을 볼 위험이 있습니다.
- **해결:** 채팅방을 구독하는 순간 서버가 그 예약의 멘토나 신청자인지 확인하고, 아니면 막습니다 (`StompChatConfig`).

## B. 포트폴리오 정리 중

### B1. 원본 코드의 화면 빌드 실패
- **문제:** 팀 원본 `develop`에서 `npm run build`가 실패했습니다. 저장소에 없는 영상 파일(`main_video1~3.mp4`)을 불러오고 있었습니다.
- **해결:** 이 영상들은 저장소에 이미 있는 `stream1~3.mp4`와 내용이 똑같은 파일이었습니다(해시 비교로 확인). 그래서 영상을 새로 올리지 않고 불러오는 경로만 바꿨습니다.
- **확인:** `npm run build` 성공

### B2. 미니 캘린더 연결이 끊긴 문제
- **문제:** 팀 코드를 합치는 과정에서 방송방 화면이 미니 캘린더에 옛날 데이터를 넘기고, 방장에게만 보이도록 바뀌어 있었습니다. 같은 코드 블록이 두 번 들어가 화면도 깨져 있었습니다.
- **해결:** 팀 저장소에 올리지 못한 제 커밋(`043b9b7`)을 넣어 일정 데이터와 등록·추가·취소 기능을 다시 연결하고, 중복 코드를 지웠습니다.

### B3. 미니 캘린더가 항상 2026년 8월로 열리는 문제
- **문제:** 미니 캘린더 시작 날짜가 `new Date(2026, 7, 27)`로 고정돼 있었습니다. 발표 당시 날짜를 넣어 둔 것으로 보입니다.
- **해결:** 오늘 날짜로 열리도록 바꿨습니다.
- **확인:** 방장 화면에서 이번 달로 열리고, 등록한 일정이 해당 날짜에 표시됨

### B4. 챗봇 의도 분류 테스트 3건 실패
- **문제:** 챗봇 질문 분류 테스트 40개 중 3개가 실패했습니다. "우리 홈페이지는 뭐 하는 곳이야?", "나는 뭘 배워야 할지 모르겠어" 같은 질문을 분류하지 못했습니다.
- **원인:** 질문을 비교하기 전에 띄어쓰기를 모두 지우는데, 비교할 키워드 중 일부(`"우리 홈페이지"`, `"뭘 배워야"`)에는 띄어쓰기가 남아 있었습니다. 그래서 절대 일치할 수 없었습니다. 또 "가르칠", "가르쳐도"는 키워드 `"가르치"`와 글자가 달라서 걸리지 않았습니다.
- **해결:** 키워드도 띄어쓰기를 지운 뒤 비교하도록 고쳤습니다. "가르칠", "가르쳐도"도 키워드에 추가했습니다. "가르쳐"를 통째로 넣지 않은 이유는 "자바 가르쳐줘" 같은 배우고 싶다는 질문까지 멘토 등록 안내로 잘못 보낼 수 있어서입니다. 테스트의 기대값은 바꾸지 않았습니다.
- **확인:** 테스트 40개 모두 통과. 실제 서버에서도 "나는 뭘 배워야 할지 모르겠어"에 정해 둔 안내가 나오는 것을 확인했습니다. 고치기 전에는 이 안내가 한 번도 나올 수 없었습니다.

### B5. 서버 전체 실행 테스트 실패
- **문제:** 서버 전체가 정상적으로 뜨는지 보는 테스트(`contextLoads`)가 실패했습니다. 실시간 통신 설정이 실제 웹 서버를 필요로 하는데, 테스트가 가짜 웹 환경에서 실행되고 있었습니다.
- **해결:** 테스트할 때 실제 웹 서버를 빈 포트에 띄우도록 바꿨습니다. 이 테스트는 DB가 필요해서 개발용 DB를 연결해 실행했습니다.
- **확인:** 테스트 통과
- 함께, 프로젝트를 처음 만들 때 생긴 뒤 쓰이지 않던 템플릿 테스트 하나를 지웠습니다.

### B6. 한글 경로에서 테스트가 실행되지 않음
- **문제:** Windows에서 폴더 경로에 한글이나 공백이 있으면 서버 테스트가 테스트 파일을 찾지 못했습니다.
- **대응:** 영어 경로에 복사해서 테스트를 실행했습니다. 서버 실행(`bootRun`)은 한글 경로에서도 문제없었습니다.

### B7. 설정 파일에 적혀 있던 비밀번호
- **문제:** 메일 비밀번호, 결제 키, 관리자 이메일이 설정 파일에, 카카오 키가 화면 코드에 그대로 적혀 있었습니다.
- **해결:** 모두 환경 변수로 옮기고, 가짜 값만 넣은 예시 파일을 만들었습니다.
- **주의:** 이 저장소에서는 지웠지만, 팀 원본 저장소의 과거 커밋에는 남아 있습니다. 그 비밀번호와 키는 주인이 새로 발급받아야 합니다.
