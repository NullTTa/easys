# 트러블슈팅

A는 프로젝트 개발 중 해결한 문제입니다. 코드 주석과 커밋에 남은 내용을 바탕으로 정리했습니다. B는 포트폴리오를 정리하면서(2026-10) 발견하고 고친 문제입니다.

## A. 개발 중 해결한 문제

### A1. 외부 LLM API → 로컬 LLM 전환
- **상황:** 처음에는 Gemini API로 챗봇을 연동했습니다 (`0021f3c`). 외부 API를 쓰면 키 관리, 호출 비용, 사용량 제한을 계속 신경 써야 했습니다.
- **결정:** Ollama의 `qwen2.5:3b`를 로컬에서 실행하는 방식으로 바꿨습니다 (`80d84c9`). `CustomLlmClient`가 `/api/chat`에 대화 메시지를 보내고, 모델명·주소·temperature는 `LlmProperties`와 환경 변수로 분리해 모델을 쉽게 교체할 수 있게 했습니다.
- **트레이드오프:** 작은 모델이라 정확도가 낮고 답을 지어내기 쉽습니다. 그래서 A2와 같은 보완 장치가 필요했습니다.

### A2. 작은 모델이 지어내는 답 줄이기
| 증상 (코드 주석에 기록된 사례) | 대응 |
|---|---|
| 서비스에 없는 URL이나 기능을 만들어 냄 | LLM은 URL을 만들지 않고, 백엔드가 `ActionDto`로 이동 대상만 내려줌 |
| "방송 보고 싶어"와 "방송 만들고 싶어"를 구분하지 못함 | 시청/생성 의도를 동사로 따로 분류해 프롬프트에 명시 |
| "인기 방송"을 일반 지식(YouTube 등)으로 답함 | DB 집계 결과로 직접 응답 |
| 한글 답변에 한자·가나가 섞임 | 후처리 필터 |
| "뭘 배워야 할지 모르겠어"에 긴 일반 조언을 늘어놓음 | 되묻는 고정 안내로 처리 |

### A3. 대화 맥락이 섞이는 문제
- **상황:** "방송 보고 싶어" 다음에 "자바 문제 내줘"를 물으면 스트리밍 이야기가 섞였습니다.
- **해결:** Redis 대화 기록(`ChatSessionService`)은 유지하되, 학습 문제 출제처럼 맥락이 필요 없는 요청은 기록 없이 질의합니다.

### A4. 결제 위·변조와 결제 전 일정 등록
- 결제 승인은 서버에서만 Toss API를 호출하고, 그 전에 주문 소유자와 금액을 DB 값과 비교합니다 (`PaymentService.confirmPayment`).
- 멘토링은 "승인만으로 결제 완료 처리하지 않는다"는 원칙에 따라, 캘린더 일정을 결제 승인 성공 시점(`onMentoringPaymentConfirmed`)에만 만듭니다.

### A5. 남의 채팅방 구독
- STOMP `SUBSCRIBE` 요청을 `ChannelInterceptor`로 가로채, `/topic/mentoring/{reservationId}` 구독자가 해당 예약의 멘토나 신청자인지 확인합니다 (`StompChatConfig`).

## B. 포트폴리오 정리 중 발견하고 고친 문제

### B1. 원본 `develop` 프론트엔드 빌드 실패
- **원인:** 저장소에 없는 `main_video1~3.mp4`를 import하고 있었습니다. 로컬에만 있던 파일이며, 기존 `stream1~3.mp4`와 해시가 같은 중복 파일이었습니다.
- **해결:** 14MB 영상을 새로 추가하지 않고 import 경로만 기존 파일로 바꿨습니다.

### B2. 머지 과정에서 끊긴 미니 캘린더
- **원인:** 머지 후 `CamPage`가 미니 캘린더에 예전 props(`groupSchedules`)를 넘기고, 방장에게만 렌더링하고 있었습니다. JSX 중복 블록도 남아 있었습니다.
- **해결:** 미푸시 상태였던 본인 커밋 `043b9b7`을 반영해 `roomSchedules`와 등록·추가·취소 핸들러를 다시 연결했습니다.

### B3. 미니 캘린더가 항상 2026년 8월에서 시작
- **원인:** 초기 상태가 `useState(new Date(2026, 7, 27))`로 하드코딩돼 있었습니다 (시연 당시 날짜로 보임).
- **해결:** `useState(() => new Date())`로 바꿨습니다. 실제 화면에서 당월 표시와 일정 표시를 확인했습니다.

### B4. 챗봇 의도 분류 테스트 3건 실패
- **원인:** `normalize()`는 질문의 공백을 모두 지우는데, 일부 키워드(`"우리 홈페이지"`, `"뭘 배워야"`, `"멘토가 될"`)에는 공백이 남아 있어 비교가 항상 실패했습니다. `"가르칠"`, `"가르쳐도"`는 `"가르치"`와 음절이 달라 걸리지 않았습니다.
- **해결:** 키워드도 같은 방식으로 공백을 지운 뒤 비교하는 `containsMarker()`를 추가하고, 주석에 요구사항으로 적힌 예문의 활용형을 추가했습니다. 테스트 기대값은 바꾸지 않았습니다. `"가르쳐"` 전체는 "자바 가르쳐줘" 같은 학습 요청까지 잘못 분류할 수 있어 넣지 않았습니다.
- **결과:** 40개 전부 통과. 서버에서도 "나는 뭘 배워야 할지 모르겠어"가 설계된 고정 안내 경로로 처리되는 것을 확인했습니다.

### B5. `contextLoads` 실패
- **원인:** `WebSocketConfig`의 `ServletServerContainerFactoryBean`은 실제 서블릿 컨테이너가 있어야 만들어지는데, `@SpringBootTest` 기본 모의 웹 환경에는 컨테이너가 없습니다.
- **해결:** `webEnvironment = RANDOM_PORT`로 내장 서버를 띄워 검증합니다. 개발 전용 DB가 필요한 통합 테스트입니다.

### B6. Windows 한글 경로에서 Gradle 테스트 실패
- **증상:** 경로에 한글·공백이 있으면 테스트 클래스를 찾지 못합니다(`ClassNotFoundException`, 시스템 코드페이지 949).
- **대응:** 영문 경로에서 테스트를 실행합니다. `bootRun`은 한글 경로에서도 정상 동작했습니다.

### B7. 하드코딩된 비밀값
- `application.properties`에 들어 있던 메일 계정·비밀번호, Toss 키, 관리자 이메일과 소스에 있던 Kakao 키를 환경 변수로 옮겼습니다.
- **주의:** 원본 팀 저장소의 **과거 Git 이력에는 여전히 남아 있습니다.** 이 스냅샷은 이력을 가져오지 않았지만, 노출된 자격 증명은 소유자가 폐기·재발급해야 합니다.
